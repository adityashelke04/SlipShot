# Architecture and ownership

`Program` sets PerMonitorV2 before creating WPF objects, holds a single-instance local mutex and starts the tray controller. No capture runs on startup. `AppController` owns windows, hotkeys, the latest capture, queue and cancellation lifetime. `Hotkeys` owns a message-only HWND and unregisters its binding before disposal.

`IDesktopCapture` is the backend seam. `DesktopCapture` acquires a monitor frame once on a worker, before any selection chrome. Screen DC, memory DC and DIB have separate SafeHandle release functions. The original selected GDI object is restored before deletion; GDI is flushed before pixel access. Pixel bytes become a frozen WPF bitmap and native handles are released. Cancellation is checked around native calls. A three-second deadline reports timeout; an uninterruptible native call retains the capture gate until it returns, preventing overlapping calls. No unsafe worker termination is attempted.

`SelectionWindow` shows only a frozen frame, with monitor-local pointer positions converted by actual rendered size to physical pixels. One monitor is an explicit boundary. It copies selected pixels into a new frozen bitmap rather than retaining a CroppedBitmap reference to the full monitor. Escape/deactivation/display change produces no capture, clipboard or file output. A capture generation must remain current before delivery. Native display disconnect and focus behavior still need real checks.

The controller uses `PreviewQueue.Replace` to expose only the newest capture, clearing pending items; old cards cannot resurface. Preview creation is suppressed while `CaptureGate.IsBusy`, and old Closed callbacks are identity-guarded. `PreviewLifetime` uses a monotonic clock:10seconds idle by default plus at most20seconds aggregate hover/focus grace, with actual gestures/copy/hidden-capture state protected. Physical cursor/foreground checks avoid stale WPF flags. A second timer phase closes after the120ms fade even if animation completion never fires. The preview is physically positioned from capture-monitor work-area coordinates. `ShowActivated=false`, `WS_EX_NOACTIVATE`, `WS_EX_TOOLWINDOW` and `SWP_NOACTIVATE` are applied together. Explicit Edit activates only on interaction. All owned windows request WDA_EXCLUDEFROMCAPTURE; hide-before-capture plus DWM flush is the fallback. No SetForegroundWindow calls.

`EditDocument` owns an immutable frozen source and validated immutable snapshots. Crop and annotation bounds stay in source pixels. Annotation points are copied at commit so live gesture lists cannot mutate history. At most 80 snapshots are retained, reduced further by a weighted annotation-memory budget. Per-document limits: 1,000 objects, 100,000 stroke points and 100,000 text characters. Weak saved-state tracking avoids retaining evicted history. `DocumentViewModel` exposes observable tool/selection/dirty/undo state; the editor handles pointer capture and preview gestures, committing once on release. Escape/lost capture discards transient state.

`DocumentRenderer` is the shared flattening authority for editor output, PNG, JPEG, clipboard and pins. It clips to crop, paints source, draws annotations, and paints integer-expanded opaque redactions last. Cropping translates only the final render; source coordinates never depend on zoom or DPI. JPEG adds an explicitly configured opaque background. `ImageFiles` re-renders flattened pixels to prevent propagating metadata, writes a unique sibling temp file, verifies decode dimensions and atomically moves to the destination. Overwrite requires explicit UI confirmation; new files remain race-safe. Cleanup touches only temp files this save created.

`ClipboardWriter` accepts an injected sink. Windows writes require STA; retries dispatch to the original STA dispatcher. It retries only CLIPBRD_E_CANT_OPEN, four total attempts, with bounded waits. Editor copy failure remains a failure; preview failures use a nonactivating notification. Real interop with target applications is deferred.

`PreviewGesture` separates a click from system-threshold dragging. The native STA `DragDrop.DoDragDrop` loop uses `DragTransferStore` payloads with FileDrop, Bitmap and PNG. The controller blocks capture/reopen/forget/exit reentry during a drag; the preview defers closing and cancels through QueryContinueDrag before unwinding. Dismissal pauses for held pointer and active OLE drag even outside the card. `DragPayload`, inside WPF's native-marshaled `DataObject`, distinguishes actual GetData reads from enumeration/format queries. Copy acceptance or any payload read preserves the generated file and managed PNG stream for late consumers, including a target that reports None or throws after taking data. Unconsumed cancellation still removes its file. Retained files survive process exit; 24-hour expiry is opportunistic on later explicit drags. Exact GUID filenames, flat owned-directory enumeration, reparse-point guards and 1024-file/256-MiB caps bound cleanup. This is explicit user-directed export, not automatic capture history.

`SettingsStore` uses versioned JSON beside the portable app. Missing/corrupt/oversized/unsupported files yield defaults and a nonsensitive warning. Settings writes are atomic. No screenshot content is serialized to settings or logs. The app contains no network clients. `SLIPSHOT_DRAG_DIAGNOSTICS=1` opts into local JSONL diagnostics: correlation ID, version/PID, elapsed time, format category, dimensions/encoded size, native effect, button state, retention, exception type/HRESULT. Pixels, filenames, paths, window titles and exception messages are excluded. Logs rotate at 1 MiB to one previous file; target request chatter is capped per drag. Unavailable log storage cannot break the transfer.

`ResourcePolicy` budgets projected image buffers against 512 MiB, including three transient buffers for capture/export, and enforces a 32-megapixel per-frame limit. This is a conservative accounting policy, not an assertion about measured process working set (WPF/native caches and object overhead add to it). Native images are owned by safe handles; managed image memory is released by removing references and normal GC, not forced collections. Editors/pins are capped at three each. Saved files are never deleted on dismissal/close.

The .NET project is conventional and dependency-free at runtime beyond the Windows Desktop framework. Programmatic WPF avoids a second UI framework. The fallback compiler uses runtime assemblies rather than reference packs because the SDK is missing; an SDK build and native smoke test are release gates for public distribution.

Since0.2.4, explicit Save uses `ImageFiles.QuickSave` and the configured folder (default same local drive/SlipShot Captures). It creates directories only on Save, retries filename races within a fixed budget, and never overwrites. Save As stays a separate dialog action. Both paths share rendering/encoding; MarkSaved occurs only after a verified completed file. Missing or unwritable folders report errors without redirecting to a different destination.

Since0.2.5, the controller uses `ImageFiles.SaveDocument`, which skips writing a snapshot already saved to an existing file. Capture records retain a baseline document. Editors fork immutable snapshots with independent undo/edit state while sharing weakly keyed export receipts; weak subscriber references keep save buttons synchronized without retaining closed editors. A receipt is recorded only after successful encoding. Deleted files invalidate receipts on interaction; explicit overwrites invalidate older receipts, including other live captures. No background file polling or global pixel-hash deduplication is performed. Actual edits may produce a separate file; repeated unchanged Save does not.
